# novel-write - 正文写作引擎

## 目标

写出完整、可读、可继续的小说章节。大纲提供方向和约束，正文必须呈现场景、选择、阻力、感官、潜台词和变化，不能把章纲逐条改写成叙述。

## 写前闸门

运行：

```text
python tools/outline_guard.py preflight --project-root <项目根> --part <部号> --volume <卷号> --chapter <章号>
```

缺少总纲、任一部纲、任一卷方向、目标卷详纲、卷章节索引或当前章纲时，暂停写作并补齐对应层级。不得使用“最低约束模式”绕过缺失章纲。

若当前会话没有前文记忆，先完整执行 `novel-continue.md`；没有 `continuation_context.md` 时不得把“读了最后一章”视为恢复完成。

随后运行伏笔到期检查：

```text
python tools/foreshadowing_tracker.py due --project-root <项目根> --part <部号> --volume <卷号> --chapter <章号>
```

将 `due`、`overdue` 和已触发的 `conditional` 项写入任务卡。`not_due` 项保持沉默；`available` 项只有在自然服务本章事件时才处理。

## 记忆加载

按顺序读取：

1. 全书总纲和主设定，只提取与当前章有关的全书约束。
2. 当前部纲，确认本章处于本部哪一段变化中。
3. 当前卷纲和剧情单元，确认本章的卷级功能。
4. 卷章节索引、当前章纲、上一章正文末尾和上一章摘要。
5. 当前人物状态、时间线、伏笔账本和本章到期检查、用户文风偏好。
6. 只有遇到久未出现的人物、地点或伏笔时，才运行 RAG 检索历史正文。

整理成一页以内的写作任务卡：本章欲望、阻力、变化、场景链、必须兑现、伏笔决定、必须延迟、章末状态。任务卡不写入正文。

## 正文流程

### 1. 确定叙事重心

用一句话回答：“读者在本章主要经历什么变化？” 若答案只是“知道了一些信息”，为信息安排行动、关系或代价载体。

### 2. 写完整初稿

- 从正在发生的变化进入场景，避免用设定摘要开场。
- 每个场景让人物带着欲望进入，经过阻力和选择后以不同状态离开。
- 让信息通过行动、对话、误解、物件或环境显现。
- 对话同时服务表层目的和人物关系，避免轮流解释背景。
- 节奏服从本章体验；高潮章可以紧，余波章必须给人物和读者消化空间。
- 章末完成本章的变化，同时产生具体的新问题、代价或选择。
- 达到章纲目标字数的正负 10%，一次写完，不留占位符。

### 3. 内容审查

先核对故事，再处理句子：

- 本章结果是否由人物行动和先前条件造成。
- 人物是否只知道其有渠道知道的信息。
- 能力、物资、位置、时间和关系是否连续。
- 本章是否兑现章纲核心任务，又避免提前解决更高层冲突。
- 开头是否承接，结尾是否为下一章提供可执行起点。

发现结构问题时修改场景，不用解释句掩盖因果缺口。

### 4. 语言润色

按项目既有风格调整视角、句长、段落和对白。需要时读取 `style-adapter.md`、`dialogue-writing.md`、`scene-description.md` 或对应类型指南。运行 `anti_ai_check.py` 可辅助定位机械表达，但脚本分数不能替代人工判断。

### 5. 落盘与写后记忆

正文写入 `正文/第NN部/第NNN卷/第NNNN章-章名.md`。随后更新：

- 章节事实摘要和下一章承接点。
- 人物位置、目标、知识、关系、伤势和资源。
- 时间线与并行事件。
- 运行伏笔候选检测，语义确认后记录新增、强化、部分回收、完全回收或延期；每条都写明原因和原文证据。
- 刷新所有活跃伏笔在埋设章前后各 2 章的摘要上下文。
- `master_state.json` 的当前部、卷、章和字数。

伏笔命令：

```text
python tools/foreshadowing_tracker.py detect --chapter-file <正文路径>
python tools/foreshadowing_tracker.py refresh-context --project-root <项目根> --chapter <章号> --window 2
python tools/foreshadowing_tracker.py validate --project-root <项目根>
```

只有正文文件和以上必要记忆均写入成功，才报告该章完成。

## 边界处理

- 卷末章：写后立即执行卷收尾，不直接跳到下一卷。
- 部末章：先完成卷收尾，再执行部收尾。
- 全书末章：先执行单章审查，再运行全书收尾清单。

## 完成标准

- 正文完整，无占位符，字数达标。
- 与总纲、部纲、卷纲、章纲和动态状态一致。
- 写后记忆和伏笔账本已更新，下一章有明确承接点。
