# novel-continue - 新会话续写恢复

## 目标

在没有上一会话记忆时，从项目文件恢复整本小说的结构、已写内容和当前状态，再继续创作。不能只读最后一章，也不能依赖用户重新讲述全部背景。

## 触发

用户说“续写”“继续写”“接着上次写”，或新会话要求写已有项目的下一章时，先执行本模块，再进入 `novel-write`。

## 1. 建立全书清单

运行：

```text
python tools/continuation_scanner.py scan --project-root <项目根> --write-inventory
python tools/outline_guard.py status --project-root <项目根>
```

读取 `.webnovel/continuation_inventory.json`。核对总纲、全部部纲、全部卷纲、卷章节索引、已写正文、章节摘要、动态记忆和收尾文件的实际数量。状态文件与真实文件冲突时，以真实文件为准并记录差异。

## 2. 浏览整本书的结构

按顺序读取：

1. 全书总纲。
2. 每一部部纲，不跳过尚未写到的后续部。
3. 每一卷卷方向；已进入或已写过的卷再读详纲和剧情单元。
4. 所有已写卷的完整章节索引。

生成一份全书结构压缩图：每部一句阶段变化，每卷一句叙事任务和卷末状态，当前卷标出已完成与未完成区间。

## 3. 浏览整本书的大致内容

按章号顺序读取所有章节事实摘要。可以分批读取，但覆盖率必须达到 100%。

若扫描器报告摘要缺失：

1. 按章号分批读取缺失章节正文。
2. 为每章生成 `.story-system/chapter_summaries/第NNNN章.json`，记录事实、人物状态变化、伏笔变化、未解问题和下一章承接点。
3. 重跑扫描器，直到 `summary_coverage` 为 100%。

摘要存在时不需要通读全部历史正文；但必须读取全部摘要，才能声称已浏览整本书的大致内容。

## 4. 恢复动态状态

读取人物状态、时间线、项目记忆、卷/部收尾和伏笔账本。运行当前章节的伏笔到期检查，列出活跃、临期、到期和逾期项。核对状态文件中的当前位置与实际最大正文章号。

## 5. 深读最近内容

完整读取最近 3 章正文、它们的章纲和摘要。若刚跨卷、跨部、发生高潮或更换视角，扩大到最近 5 章并读取对应卷/部收尾。

然后读取下一章章纲、后续 2 章索引方向和当前卷详纲，确认下一章不是只承接最后一句，而是承接当前剧情阶段。

## 6. 生成续写上下文

写入 `.webnovel/continuation_context.md`，包含：

- 扫描时间、最大正文章号和摘要覆盖率。
- 全书部卷结构压缩图。
- 已写剧情按卷摘要和当前剧情位置。
- 当前人物、关系、资源和时间状态。
- 活跃伏笔及回收紧迫度。
- 最近 3-5 章的连续因果链。
- 下一章目标、必须承接、不可违反和后续两章方向。
- 发现的文件冲突、缺失信息和采用的处理。

该文件是本次新会话的会话级记忆，不替代原始总纲、部纲、卷纲和动态账本。

## 写作闸门

仅当以下条件均满足才进入 `novel-write`：

- 全书结构扫描通过。
- 所有已写章节都有事实摘要，且代理已按顺序读取。
- 最近正文已深读。
- 动态状态和伏笔账本已读取。
- 下一章章纲存在并通过写前校验。
- `continuation_context.md` 已生成。

任何条件未满足时先修复恢复链路，不凭猜测续写。
