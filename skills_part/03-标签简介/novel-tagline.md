# 📋 novel-tagline — 标签组合与简介生成

## 概述
基于题材和设定，生成最优化标签组合（SEO/推荐算法友好）以及高转化率的吸睛简介。

## 所属阶段
第三阶段：标签与简介

## 输入
- 选题策划书（novel-topic 产出）
- 核心设定（novel-settings 产出）

## 核心流程

### Step 1：标签策略
- **题材标签**（2-3 个）：如"玄幻""都市""科幻"
- **核心标签**（3-5 个）：如"系统""重生""无敌流""后宫"
- **热门标签**（2-3 个）：当前平台热搜标签（如"沙雕""脑洞"）
- **长尾标签**（2-3 个）：精准细分标签（如"网游竞技""宠物养成"）
- 标签组合优化：确保覆盖 **题材→卖点→爽点→受众** 四个维度

### Step 2：多版本简介生成

| 方案 | 风格 | 适用场景 |
|------|------|---------|
| A：悬念式 | 以问题结尾，激发好奇心 | 悬疑/解密/烧脑题材 |
| B：冲突式 | 开篇即冲突，展示核心矛盾 | 玄幻/都市/商战 |
| C：成就式 | 列举主角成就/金手指/成长 | 无敌流/系统流/升级流 |
| D：共情式 | 引发读者情感共鸣 | 现实/情感/治愈 |

### Step 3：简介质量检查
- [ ] 是否在 200 字内传达了核心设定？
- [ ] 是否有明确的冲突/悬念？
- [ ] 是否包含至少 1 个独特卖点？
- [ ] 是否符合平台字数限制？
- [ ] 是否包含明确的阅读理由（"为什么读者要看"）？

### Step 4：A/B 测试建议
- 主推方案（推荐用于平台首发）
- 备选方案（用于更换简介时测试）
- 适配不同平台的精简版（番茄/起点/晋江各有字数限制）

## 产出文件
```
设定/标签与简介.md
```
内容结构：
- 标签组合列表（含分类说明）
- 多个简介版本（至少 2 个方案）
- A/B 测试建议

## 质量闸门
- [ ] 标签覆盖 4 个维度（题材/卖点/爽点/受众）
- [ ] 简介 ≥ 2 个版本
- [ ] 每个简介 ≤ 200 字
- [ ] 包含明确的核心卖点

## 故障恢复
| 问题 | 处理方式 |
|------|---------|
| 用户对简介不满意 | 提供更多备选方案，或让用户手动修改关键句 |
| 平台字数特殊限制 | 为各平台生成适配版本 |
