# novel-plan - 卷纲规划

## 目标

把一个已确认的卷方向深化为可拆章的完整卷纲。卷纲只负责卷级因果和节奏，不在这里批量生成正文或详细章纲。

## 前置条件

- 全书总纲和全部部纲已确认。
- 所有卷至少已有 `direction-confirmed` 方向文件。
- 目标卷所属部、卷号和前后卷交接明确。

## 参数

`--volume N` 指定全书连续卷号。一次只深化一卷；用户明确要求批量时也要逐卷确认。

## 流程

### 1. 分层回读

读取全书总纲、所属部纲、目标卷方向、上一卷收尾（如有）和下一卷方向。提取不可改变的起点、终点和跨卷承诺。

### 2. 询问卷内过程

向用户确认本卷最重要的 1-3 个方向决策，例如：

- 本卷高潮最终靠什么选择或行动达成。
- 本卷必须出现/不能出现的事件与人物。
- 本卷更偏成长、关系、探索、权谋还是战争，以及希望保留的节奏。

### 3. 设计卷级因果链

产出并确认：

- 起始失衡、阶段目标、核心阻力和失败代价。
- 3-6 个剧情单元，每个单元如何导致下一个单元。
- 至少 3 次递增压力；升级必须改变选择空间，不能只是敌人更强。
- 中段不可逆转折、卷高潮、卷末结果。
- 人物弧、关系变化、资源变化、伏笔和时间线。
- 本卷闭合项、跨卷遗留项和下一卷钩子。

### 4. 用户确认并更新文件

更新原卷方向文件，不另建内容重复的文件。首行状态改为 `detailed-confirmed`，并保留“方向变更记录”，说明相对部纲卷方向表的变化及用户确认时间。

本卷计划埋设或回收的伏笔同步写入 `.story-system/foreshadowing.json`：尚未进入正文的条目标为 `planned`，必须写明设计目的、预计埋设位置、回收窗口、触发条件和计划方式。不能只在卷纲中写“埋伏笔”而不登记账本。

需要更细的剧情单元模板时读取同目录外的 `skills_part/06-剧情单元/novel-arc.md`，结果可写入卷纲同一文件或同卷的 `剧情单元.md`。

### 5. 校验

- 卷起点承接上一卷，卷终点能启动下一卷。
- 所有剧情单元服务本卷目标，没有可整体删除的游离单元。
- 高潮解决本卷冲突，但不提前解决部级或全书级冲突。
- 卷纲内没有与总纲、部纲和设定冲突的事实。

## 产出

`大纲/02-卷纲/第NN部/第NNN卷-卷纲.md`

## 完成标准

目标卷文件状态为 `detailed-confirmed`，必填项完整，用户确认，结构校验通过。
