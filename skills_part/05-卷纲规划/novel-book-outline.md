# novel-book-outline - 全书总纲与部纲

## 目标

先完成全书方向，再展开每一部。最终必须让所有部都有实质内容，后续部不能只保留名称。

## 输入

- 选题、设定、主要人物和一句话故事。
- 用户对结局、篇幅、部数和重大时间跳跃的想法。
- 既有项目中的总纲、部纲和修改记录。

## 流程

### 1. 询问全书方向

一次询问 1-3 个阻断问题，优先取得：

- 主角最终得到什么、失去什么，故事在什么状态结束。
- 全书计划分几部；划部依据是时代、地点、身份、目标还是视角变化。
- 用户已经确定的重大转折，以及明确不想采用的方向。

信息不足时给出 2-3 套可修改方案，每套都覆盖完整起点、升级和终点。用户确认前标为草案。

### 2. 生成完整部方向图

一次列出所有部。每部都写：

- 名称和在全书中的叙事功能。
- 起始状态与阶段目标。
- 核心冲突和主要对手。
- 至少一个不可逆转折。
- 高潮、结束状态和下一部交接。
- 预计卷数和篇幅区间。

检查相邻部的因果交接。第二部不能只是“冲突升级”，第三部不能只是“最终决战”；必须说明升级了什么、为何升级、人物和世界发生了什么不可逆变化。

### 3. 用户确认并落盘

用户确认完整部方向图后：

1. 写入 `大纲/00-总纲/全书总纲.md`。
2. 为每部写入独立的 `大纲/01-部纲/第NN部-部纲.md`。
3. 部纲先包含已确认的部级内容和卷方向待规划区，不能创建空文件。
4. 初始化结构清单并记录各部卷数。

如果用户暂停，把未确认内容写入 `.webnovel/drafts/`，状态保持 `draft`，不进入正式大纲目录。

### 4. 为每部规划全部卷方向

逐部询问本部核心过程、期望事件和卷数。先列全该部所有卷的方向，再请用户整体确认。确认后：

- 更新该部部纲中的完整卷方向表。
- 为每一卷建立独立方向文件，状态为 `direction-confirmed`。
- 运行结构校验，确认没有缺号、空卷或重复功能。

长篇幅时每轮可处理一部，但所有部的卷方向都完成前，不得宣告全书结构规划完成。

## 完成标准

- 全书总纲的每一部均有起点、过程、转折和终点。
- 每部有独立文件，且每部的所有卷都有独立方向文件。
- 用户已确认全书方向和各部卷方向。
- `outline_guard.py status` 不报告缺失结构。
