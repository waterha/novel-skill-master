# 设定一致性检查（Setting Consistency Check）

## ⚠️ 重要变更

**本文档已升级为"契约驱动验证"模式。** 不再依赖"人手工对照检查清单"，而是由 **Reviewer Agent 自动加载设定契约（MASTER_SETTING.json）**，对每一章做自动化的设定一致性验证。

> 手工检查清单仍然保留作为兜底参考，但主要防线已移至自动化契约验证。

---

## ★ 契约验证（自动化，由 Reviewer Agent 执行 + 脚本辅助）

写章完成后，Reviewer Agent 必须执行以下自动化验证。这些验证**不需要人参与**，由 Agent 直接对照 `.story-system/MASTER_SETTING.json` 完成。

> **结构性校验**：MASTER_SETTING.json 的完整性由 `tools/project_doctor.py check` 自动完成（检查 power_system.levels/characters/world_rules 各字段是否存在）。
> Reviewer Agent 只需关注**语义层面**的契约验证（角色能力是否符合、世界规则是否被违反等）。

### 验证流程

```
Step 1: 加载 MASTER_SETTING.json（当前有效版本）
Step 2: 加载 character_states.json（当前角色状态快照）
Step 3: 逐项执行以下验证
Step 4: 输出验证报告（blocking/major/minor/suggestion）
```

### 验证项

#### 1. 角色能力阶段契约验证（通用，不限题材）
- 确定本章涉及哪些能力维度（力量/知识/资源/社会地位/情感——以契约中 enabled:true 的维度为准）
- 提取正文中角色展示的所有能力、知识、资源使用、行为表现
- 对照该维度当前阶段的 `capabilities` 列表（确认授权）和 `limits` 列表（确认禁区）
- 如果出现 `limits` 中的行为 → **blocking**
- 如果出现 `capabilities` 中不存在且 `limits` 中未提及的行为 → **major**（询问是否登记遗漏）

#### 2. 能力发展时间线验证
- 确定角色各能力维度在正文中展示的实际阶段
- 对照 `capability_timeline` 中该章节区间应有的阶段范围
- 如果实际阶段低于预期超过 2 阶 → **suggestion**（成长偏慢，需确认是否故意设计）
- 如果实际阶段高于预期超过 1 阶 → **blocking**（发展过快，除非 change_log 有记录）

#### 3. 信息壁垒验证（如有 info_barriers）
- 提取正文中角色获得的关键信息
- 对照 `info_barriers` 中的时间节点
- 如果在禁区章节之前获得禁忌信息 → **blocking**

#### 4. 世界规则验证
- 提取正文中的关键事件（大面积法术释放、跨越宗门边界、突破世界限制等）
- 对照 `hard_rules` 列表
- 违反 `can_break: false` 的规则 → **blocking**
- 违反 `can_break: true` 但未满足 `break_condition` → **major**

#### 5. 角色性格一致性验证
- 主角行为是否违反 `forbidden_actions`
- 未揭示反派是否提前暴露 `forbidden_before_reveal` 中的设定
- 以上违规 → **blocking**

#### 6. 伏笔验证
- 检查是否有伏笔在 `must_not_be_revealed_before` 指定的章节之前被揭示
- 检查 `status: planted` 的伏笔是否在距离 `planned_reveal_chapter` 超过 2 倍范围时仍未被处理
- 提前揭示 → **blocking** / 遗忘超期 → **major**

#### 7. 跨章连续性验证（每 10 章 + 卷结束时执行）
- 加载 `.story-system/chapters/*/fulfillment.json` 中所有章节的实体状态
- 追踪物品/角色位置的跨章连续性
- 检测角色 `known_info` 的一致性（不会"忘记"已知道的信息）
- 检测时间线连续性（日期、季节无跳跃矛盾）
- 检测角色关系变化的连续性（言情/情感题材尤其重要）

## ★ 设定变更触发流程

当自动化验证发现 blocking 违规时：

```
┌─ 设定违规报告 ────────────────────────────────┐
│ 违规类型：能力阶段违规（通用）                   │
│ 详情：主角在第 27 章展示了超出当前阶段的           │
│       能力/知识/资源                            │
│       但契约中当前阶段"阶段一"的 limits           │
│       规定该阶段不可使用此能力/知识/资源           │
│ 建议：                                          │
│   [1] 走设定变更流程 → 更新 MASTER_SETTING       │
│   [2] 修改正文 → 删除或替换该行为                │
│   [3] 添加代价 → 使用但承受后果（推荐）           │
└─────────────────────────────────────────────────┘
```

**严禁静默跳过**。三种方案必须三选一后，才能继续后续流程。

## 手工检查清单（兜底参考）

以下清单保留作为**自动化验证未能覆盖的场景**的手工检查。不建议依赖此清单作为主要防线。

### 一、角色一致性

#### 基础信息
- [ ] 角色姓名、年龄、外貌前后一致
- [ ] 角色的能力/技能没有突然出现或消失
- [ ] 角色的性格没有无故改变（除非有成长弧线支撑）
- [ ] 角色的背景故事在后续提及时不矛盾

#### 能力边界
- [ ] 角色使用的能力没有超出设定中的等级限制
- [ ] 角色没有忘记自己已经知道的信息
- [ ] 角色的成长速度符合设定中的天赋描述

---

### 二、世界观一致性

#### 物理规则
- [ ] 世界的基本物理规律前后一致
- [ ] 魔法/灵力的使用方式没有临时改变
- [ ] 特殊规则的代价/限制被持续遵守

#### 时空规则
- [ ] 时间线连贯，没有日期矛盾
- [ ] 距离/旅行时间合理
- [ ] 季节/天气变化合理

---

### 三、力量体系一致性

- [ ] 等级划分在全文保持统一
- [ ] 突破条件和代价没有临时改变
- [ ] 力量天花板没有被突破（除非是刻意设计）
- [ ] 克制关系没有被无视

---

### 四、势力一致性

- [ ] 势力间的同盟/敌对关系没有无故改变
- [ ] 势力的资源和能力没有膨胀或缩水
- [ ] 势力的内部规则和等级被持续遵守

---

### 五、时间线一致性

- [ ] 事件顺序符合时间线
- [ ] 角色年龄随时间增长
- [ ] 已发生的事件在后续被正确引用
- [ ] 倒计时/期限被遵守
- [ ] 伏笔的埋设和回收时间合理

---

## 检查频率

| 阶段 | 检查方式 | 说明 |
|------|---------|------|
| 写章时（即时） | **自动化验证** | 每次 novel-write Step 3 执行，无需人工参与 |
| 创作期 | **自动化验证** | 每章完成后 Reviewer Agent 自动执行 |
| 每10章 | **自动化 + 跨章回归** | 加载多章 fulfillment.json 做连续性扫描 |
| 卷结束 | **自动化 + 手工兜底** | 全卷扫描 + 手工检查列表中未覆盖的项 |
| 全书完结 | **自动化 + 手工通读** | 全书通读检查 |

---

## 设计哲学

```
旧模式：人写 → 人检查 → 人漏了 → 崩塌
新模式：人写 → Agent 自动验证契约 → 违规即时拦截 → 始终一致
```

自动化验证不是要取代作者的判断，而是**在作者忘记的时候兜底**。长篇小说动辄几十万到几百万字，没有人能记住所有设定。契约的存在，就是为了让机器替人记住那些不该被违反的边界。
