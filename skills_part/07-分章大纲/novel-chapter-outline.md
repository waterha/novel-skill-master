# novel-chapter-outline - 分章大纲

## 目标

先列全当前卷的章节方向，再逐章深化。每章有独立文件，正文可以只加载当前章需要的记忆。

## 前置条件

- 目标卷卷纲状态为 `detailed-confirmed`。
- 剧情单元、章数范围和卷末结果明确。
- 上一卷收尾和当前人物状态可读取。

## 两阶段流程

### A. 完整章节索引

1. 询问用户本卷预计章数、章节长度和希望重点展开的段落。
2. 一次列全本卷所有章节，不因输出长度省略后半卷。
3. 每章写明章号、暂定章名、目标、冲突、转折或发现、结果、章末钩子、所属剧情单元。
4. 对照伏笔账本，把计划埋设、强化、部分回收或完全回收的伏笔 ID 写入对应章节；检查目标回收窗口是否有实际章节承载。
5. 检查本卷事件链全部被章节覆盖，相邻章的“结果 → 新问题”能衔接。
6. 用户整体确认后写入 `卷章节索引.md`。

若章节很多，先使用紧凑表格完成全量索引，再分批深化。不能先写前十章详纲、把后续章节留空。

### B. 独立章节详纲

按 5-10 章一批深化。每章使用 `references/guides/novel-project-schema.md` 的单章章纲字段，至少包含 2 个完整场景，并写清：

- 承接上一章的具体状态。
- 每个场景中人物的欲望、阻力、行动、结果和因果转场。
- 本章造成的人物、关系、信息或资源变化。
- 章末结果和下一章如何承接。
- 本章涉及的伏笔 ID、动作类型和处理边界；没有伏笔任务时明确为空，不临时硬塞。

每批先展示方向上的关键选择并询问用户；确认后将每章分别写入 `第NNNN章-章纲.md`。每批完成后报告已写章号和下一批章号，状态保持进行中直至整卷全部完成。

## 校验

- 章号连续且与章节索引一一对应。
- 每章都推进至少一个卷级目标，同时保留场景自身的生活质感。
- 不连续重复同一种冲突、揭示或章末钩子。
- 卷高潮拥有足够铺垫，卷末完成卷纲的闭合与交接。

## 产出

```text
大纲/03-章纲/第NN部/第NNN卷/
  卷章节索引.md
  第NNNN章-章纲.md
```

## 完成标准

章节索引已获用户确认；目标写作章的独立章纲已确认；全部文件通过写前结构校验。
